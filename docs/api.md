# API guide

## Build and execute

Create `IndexSpace(id, size, kind, basis, fiber)`, then ordered `Index` values.
Create `NodeSpec(name, indices)` for metadata-only construction, or a numerical
`Node(name, data, indices)` from `ricci.backends.torch` and use its `.spec`.

Build `Graph(nodes, edges=(), batches=(), outputs=())`. Ports refer to input node
names and zero-based axes. Construction validates the entire expression. Scalar
outputs use `outputs=()`; all free axes must otherwise be declared.

```python
from ricci.planning import plan
from ricci.backends.torch import execute

compiled = plan(graph, strategy="greedy", max_intermediate=1_000_000)
print(compiled.ir.equation)
print(compiled.estimated_flops, compiled.largest_intermediate_elements)
# bindings maps each node name to a live torch.Tensor
result = execute(compiled, bindings)
loss = result.data.square().sum()
loss.backward()
```

`contract(graph, bindings, strategy="direct")` is the convenience form. Both return
a `Node` with result data and ordered surviving index metadata. Use fresh bindings
for each training step. `plan.cache_info()` exposes cache statistics.

## Tensor policy

Execution accepts dense strided floating-point and complex tensors. All operands
must share dtype/device. Noncontiguous views are accepted. Inputs are never silently
cast, moved, cloned, detached or converted to NumPy. Sparse/meta/integer tensors
are rejected by the initial executor. Caller in-place mutations remain subject to
normal PyTorch autograd rules; the wrapper does not own or protect storage.

## Metadata exchange

Install the `interop` extra. `GraphDocument.from_graph(graph).model_dump_json()`
exports a versioned metadata-only document. Reconstruct with
`GraphDocument.model_validate_json(text).to_graph()`. Pydantic validates JSON syntax
and bounds; `to_graph()` validates topology and mathematical contracts. Neither
method executes code, fetches artifacts or serializes tensors.

The exchange profile limits graphs to 128 nodes and 32 legs per node. The executor's
52-wire bound is checked separately during lowering. The schema is generated by
`scripts/export_schema.py`; never hand-edit `schemas/ricci.graph.v1.schema.json`.

## Stable domain errors

Catch `RicciError` (a ValueError) and inspect `.code`, `.path`, or `.descriptor()`.
Messages are human-readable; use codes for automation. Pydantic `ValidationError`
indicates malformed interchange syntax before a Graph exists.

| Code | Meaning |
| --- | --- |
| INVALID_SPACE / INVALID_INDEX / INVALID_NODE / INVALID_GRAPH | Malformed core metadata |
| SPACE_CONFLICT / SPACE_MISMATCH | Inconsistent declaration or incompatible spaces |
| INVALID_VARIANCE / VARIANCE_MISMATCH | Illegal leg typing or pairing |
| INVALID_PORT / PORT_REUSED / INVALID_OUTPUT | Invalid topology/output specification |
| INVALID_BATCH / BATCH_REDUCTION | Invalid retained alignment or implicit batch sum |
| SHAPE_MISMATCH / BINDING_MISMATCH | Operands do not satisfy the graph |
| BACKEND_MISMATCH / UNSUPPORTED_DTYPE | Device/dtype policy violation |
| INVALID_ARGUMENT / INVALID_DOMAIN | Unsupported helper inputs/semantics |
| MISSING_DEPENDENCY / UNSUPPORTED_OPERATION | Missing extra or unimplemented execution feature |
| RESOURCE_LIMIT | Planned intermediate-size budget rejected |

Backend operational exceptions (e.g. allocation failure) may still propagate.
A future service adapter must translate those without disguising them as valid
scientific results, and must enforce its own execution/resource limits.
